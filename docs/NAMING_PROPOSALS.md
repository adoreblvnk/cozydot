# Naming Decisions

Use this order when choosing a name:

1. Preserve exact upstream names for identifiers, commands, paths, formats, payload fields, and values that Cozydot directly reads or writes.
2. Name Cozydot configuration after stable user intent, not a backend implementation detail.
3. Use one concise term for the same concept across Cozydot's schema and source.
4. Prefer the shortest established term that remains precise in context.
5. Rename only to fix ambiguity, inaccuracy, or a language-convention violation.

The table records accepted changes and their pre-implementation locations. Original proposal numbers are retained; proposal 7 was rejected and omitted. `dotfiles/**` is excluded. `src/operations/dotfiles.rs` remains in scope because it is Cozydot source.
