# Configuration reference

Cozydot reads one active file from
`${XDG_CONFIG_HOME:-$HOME/.config}/cozydot/cozydot.yaml`. The only accepted
configuration version is `1.0.0`.

## Using a preset

```console
$ cozydot init [--preset cozydot|full|cli|vm]
$ cozydot apply
```

`init` writes the selected embedded preset to the active path and installs the
embedded dotfiles. It defaults to `cozydot` and needs no checkout or network
access. Files changed by the user, unmanaged files, and obsolete managed files
are preserved. Consequently, selecting another preset does not replace an
active configuration that has been edited since `init` last wrote it.

The shipped presets are:

| Preset | Purpose |
| --- | --- |
| `cozydot` | Daily-driver GNOME/Cinnamon workstation |
| `full` | Practical larger workstation preset; not an every-field test fixture |
| `cli` | Smaller command-line package set; it still requires GNOME or Cinnamon |
| `vm` | Smaller Ubuntu/Debian GNOME guest using managed official APT sources |

`configs/cozydot.yaml` is the manually maintained base. Do not edit
`configs/full.yaml`, `configs/cli.yaml`, or `configs/vm.yaml` directly;
`scripts/generate-configs.sh` derives them from the base. The build embeds all
four snapshots. The active `cozydot.yaml` is user-owned after it is edited and
is never regenerated by that script.

## Support boundaries

The project targets Debian, Ubuntu, Pop!_OS, and Linux Mint on `x86_64`,
`aarch64`, and 32-bit ARMv7 hosts. In configuration these architectures are
named `amd64`, `arm64`, and `arm32`. Other host architectures and architecture
selector keys are rejected.

The parser also recognizes the distro IDs `zorin`, `deepin`, `kali`, and
`tails` for platform identification; these distro IDs are not additional
released support targets.
Managed official APT sources have their own narrower matrix described under
`system.apt.sources`.

Desktop detection normalizes GNOME to `gnome`, Cinnamon to `cinnamon`, and all
other or absent desktop environments to `none`. Only GNOME and Cinnamon have
desktop-setting backends.

## Document rules

The root is a mapping with this exact shape:

```yaml
version: 1.0.0
system: ...
packages: ...
tools: ...
fonts: ...
dotfiles: ...
integrations: ...
desktop: ...
updates: ...
```

`version` is required and must be the string `1.0.0`; all other top-level
fields are optional. An omitted field requests no action and generally
preserves existing state. There are no implicit configuration defaults.

| Field | Required and accepted value | Omission and interactions |
| --- | --- | --- |
| `version` | Required; exactly `1.0.0` | Selects this configuration contract |
| `system` | Optional mapping | Omission requests no system policy changes |
| `packages` | Optional mapping | Omission requests no package changes |
| `tools` | Optional mapping | Omission requests no tool installation |
| `fonts` | Optional mapping | Omission requests no font action |
| `dotfiles` | Optional mapping | Omission requests no dotfile action |
| `integrations` | Optional mapping | Omission requests no integration changes |
| `desktop` | Optional mapping | Omission requests no desktop changes |
| `updates` | Optional mapping | Omission requests no update actions |

These rules apply recursively:

- Unknown fields and duplicate mapping keys are rejected.
- Explicit `null`, empty mappings, and empty sequences are rejected. Omit an
  unused field or section instead.
- Every sequence is non-empty and has unique values unless it contains
  structured definitions, whose identities are checked separately.
- YAML directives, tags, anchors, aliases, and multiple documents are rejected.
- Scalar types are exact. Numbers and booleans are not coerced to strings.
- Fields described as “true only” reject `false`; omission is the sole no-op
  representation.
- Loading performs platform-independent validation. `apply` then validates the
  detected platform and all native repository/binary selections before running
  the plan.

YAML cannot select commands, shell fragments, managers, manager flags, lock
paths, profiles, plugins, includes, interpolation, arbitrary files, or raw APT
source lines.

## Scalar domains

The field tables refer to these reusable domains:

| Domain | Accepted values |
| --- | --- |
| Definition name | Starts and ends with an ASCII alphanumeric; interior characters are ASCII alphanumerics, `.`, `_`, or `-` |
| Executable basename | Starts with an ASCII alphanumeric; remaining characters are ASCII alphanumerics, `.`, `_`, `+`, or `-` |
| Debian package | Starts with lowercase ASCII or a digit; remaining characters are lowercase ASCII, digits, `+`, `.`, or `-` |
| Cargo package | Starts ASCII alphanumeric; remaining characters are ASCII alphanumerics, `_`, or `-`; no version selector |
| NPM package | Lowercase unversioned `name` or `@scope/name`; components start lowercase ASCII or digit and continue with lowercase ASCII, digits, `.`, `_`, or `-` |
| Flatpak ID | At least three dot-separated components; each starts with an ASCII letter and continues with ASCII alphanumerics or `_` |
| VS Code extension | Exactly `publisher.extension`; both lowercase components start alphanumeric and continue with alphanumerics or `-` |
| GNOME extension UUID | Exactly one `@`, non-empty sides, and only ASCII alphanumerics, `.`, `_`, or `-` |
| APT token | Starts lowercase ASCII or digit; continues with lowercase ASCII, digits, `.`, `_`, `+`, or `-`; the complete `*` is also accepted where stated |
| Duration | Human-readable `humantime` duration such as `15m`, `1h 30m`, or `2 days`; it must resolve exactly to whole seconds within the `u32` range, and zero is valid |
| Docker size | Positive decimal integer followed by lowercase `k`, `m`, or `g` |
| HTTPS URL | Absolute `https://` URL with a host and no credentials, fragment, whitespace, control characters, backslash, `$`, `{{`, or `{%` |
| SHA-256 | Exactly 64 lowercase hexadecimal characters |
| GitHub repository | Exactly `owner/repository`; owner starts/ends alphanumeric and otherwise uses alphanumerics or `-`; repository uses alphanumerics, `.`, `_`, or `-` and is not only dots |
| Asset regex | Non-empty valid Rust regex beginning with `^` and ending with `$`; matched case-sensitively against the complete asset filename |

## `system`

```yaml
system:
  require:
    distros: [ubuntu, debian]
    desktops: [gnome]
  ensure_admin: true
  apt:
    sources:
      mode: managed
      components:
        ubuntu: [main, restricted, universe, multiverse]
        debian: [main, contrib, non-free, non-free-firmware]
    unattended_upgrades: disabled
  ubuntu:
    snap: disabled
    codecs: installed
```

`system` is optional. If present, at least one child is required.

| Field | Required and accepted value | Omission, applicability, and interactions |
| --- | --- | --- |
| `system.require` | Optional mapping containing `distros` and/or `desktops` | Omission adds no user allowlist, but unrecognized or internally inconsistent platform identities still fail |
| `system.require.distros` | Optional unique list of `ubuntu`, `linuxmint`, `pop`, `zorin`, `deepin`, `debian`, `kali`, `tails` | Detected distro must occur in the list; recognized values are broader than released support |
| `system.require.desktops` | Optional unique list of `none`, `gnome`, `cinnamon` | Normalized desktop must occur in the list |
| `system.ensure_admin` | Optional, true only | Ensures administrative-group membership; omission preserves membership and membership is never removed |
| `system.apt` | Optional mapping containing `sources` and/or `unattended_upgrades` | Omission leaves these APT settings unchanged |
| `system.apt.sources` | Optional mapping | See source-mode rules below |
| `system.apt.sources.mode` | Required when sources is present: `preserve` or `managed` | `preserve` does not rewrite official sources; `managed` reconciles Cozydot-owned official source definitions |
| `system.apt.sources.components` | Required with managed, forbidden with preserve; non-empty map keyed by `default`, `ubuntu`, `linuxmint`, `pop`, `zorin`, `deepin`, `debian`, `kali`, or `tails`, with list values from `main`, `restricted`, `universe`, `multiverse`, `contrib`, `non-free`, and `non-free-firmware` | Selected by exact distro, then upstream family, then `default` |
| `system.apt.unattended_upgrades` | Optional: `enabled` or `disabled` | Omission preserves current state; enabling installs the `unattended-upgrades` package and enables/starts its service, while disabling writes periodic settings off, disables/stops `unattended-upgrades.service`, and purges the `unattended-upgrades` package when installed |
| `system.ubuntu` | Optional mapping containing `snap` and/or `codecs` | Planned on Ubuntu-family hosts; represented as skipped on Debian-family hosts |
| `system.ubuntu.snap` | Optional: `enabled` or `disabled` | Omission preserves Snap state; enabling installs `snapd` and enables/starts its socket. **Warning:** disabling irreversibly removes every installed Snap with `snap remove --purge`, disables/stops Snap units, purges `snapd`, recursively deletes `$HOME/snap`, `/snap`, `/var/snap`, and `/var/lib/snapd`, and publishes Cozydot's no-Snap APT pin |
| `system.ubuntu.codecs` | Optional; only `installed` | Omission preserves codec state; removal is not modeled |

Component-map keys are `default`, `ubuntu`, `linuxmint`, `pop`, `zorin`,
`deepin`, `debian`, `kali`, and `tails`. Values are non-empty unique lists from
`main`, `restricted`, `universe`, `multiverse`, `contrib`, `non-free`, and
`non-free-firmware`.

Managed official sources are accepted only for exact Ubuntu, Debian, and Kali;
derivatives must use `preserve`. Ubuntu codenames are `jammy`, `noble`,
`questing`, and `resolute`. Debian codenames are `bullseye`, `bookworm`, and
`trixie`. Kali uses `kali-rolling`. Ubuntu permits its four Ubuntu components;
Debian `bullseye` omits `non-free-firmware`, later Debian releases permit it,
and Kali permits the four Debian-family components. This managed-source matrix
does not expand the project's released support targets.

## `packages`

```yaml
packages:
  apt:
    remove: [old-package]
    install: [package-name]
    repositories: []
  flatpak: [org.example.Application]
  cargo: [crate-name]
  npm: [package-name, "@scope/package-name"]
  binaries: []
```

`packages` is optional. If present, at least one child is required. The empty
lists above illustrate placement only and are not valid configuration values.

| Field | Required and accepted value | Omission and interactions |
| --- | --- | --- |
| `packages.apt` | Optional mapping containing `remove`, `install`, and/or `repositories` | Omission requests no APT package/repository action |
| `packages.apt.remove` | Optional unique list of Debian packages | Purged before installs; an entry cannot also be owned by either install source |
| `packages.apt.install` | Optional unique list of Debian packages | Cannot duplicate a repository-owned package |
| `packages.apt.repositories` | Optional non-empty list of repository definitions | Repository names, key paths, and owned packages must be unique |
| `packages.flatpak` | Optional unique list of Flatpak IDs | Uses Cozydot's fixed per-user Flathub policy |
| `packages.cargo` | Optional unique list of Cargo packages | Requires `tools.rust` |
| `packages.npm` | Optional unique list of NPM packages | Requires `tools.node` |
| `packages.binaries` | Optional non-empty list of binary definitions | Binary names and all command ownership must be globally unique; definitions without the native architecture selector are skipped on that host |

### APT repositories

Suite/components form:

```yaml
- name: example
  key: https://example.com/key.asc
  key_path: /etc/apt/keyrings/example.asc
  urls:
    ubuntu: https://example.com/ubuntu
    debian: https://example.com/debian
    default: https://example.com/repository
  suite: system
  components: [main]
  packages: [example]
```

Exact-path form:

```yaml
- name: example
  key: https://example.com/key.asc
  key_path: /usr/share/keyrings/example.gpg
  urls:
    default: https://example.com/repository
  path: pool/stable/
  packages: [example]
```

| Field | Required and accepted value | Interactions |
| --- | --- | --- |
| `packages.apt.repositories[].name` | Required definition name | Stable identity and exact basename of `/etc/apt/sources.list.d/<name>.list`; must be unique |
| `packages.apt.repositories[].key` | Required HTTPS URL | The source URL for the signing key |
| `packages.apt.repositories[].key_path` | Required absolute path under `/etc/apt/keyrings/` or `/usr/share/keyrings/` ending with `.asc` or `.gpg` | Destination where the keyring is saved; file stem must be a valid definition name |
| `packages.apt.repositories[].urls` | Required non-empty HTTPS URL map keyed by `default`, `ubuntu`, `linuxmint`, `pop`, `zorin`, `deepin`, `debian`, `kali`, or `tails` | Selection is exact distro, upstream family, then `default` |
| `packages.apt.repositories[].suite` | Conditionally required with `components`; APT token, `*`, or reserved `system` | Forbidden with `path` |
| `packages.apt.repositories[].components` | Conditionally required with `suite`; non-empty unique list of APT tokens or complete `*`; `system` is forbidden | Forbidden with `path` |
| `packages.apt.repositories[].path` | Conditionally required when `suite` and `components` are omitted; `./` or definition-name path segments ending in `/` | Forbidden with `suite` or `components`; absolute paths, empty segments, `.`/`..` interior segments, and backslashes are invalid |
| `packages.apt.repositories[].packages` | Required non-empty unique list of Debian packages | A package can have only one install owner |

Repository URL-map keys are the same nine distro/default keys accepted by the
official-source component map. `suite: system` uses the exact distro codename
when an exact-distro or `default` URL wins, and the base codename when an
upstream-family URL wins. The resolved codename must be an APT token.

Exactly one repository layout is required: `suite` together with `components`,
or `path` by itself.

### Key and Source Semantics

Each APT repository must specify a `key_path` defining the target path for the signing key. The following rules govern its execution and placement:
- **Path domain**: The `key_path` must use the canonical spelling of an absolute direct child of `/etc/apt/keyrings/` or `/usr/share/keyrings/`. The file stem must be a valid definition name, and key paths must be unique across repositories.
- **Output semantics**: If the `key_path` ends with `.asc`, the processed key is exported as ASCII-armored bytes. If it ends with `.gpg`, it is exported as binary bytes.
- **Source-list destination**: The repository configuration is written to `/etc/apt/sources.list.d/<name>.list`, where `<name>` is the repository's definition `name` exactly.
- **Authoritative replacement**: Both the keyring file at `key_path` and the `.list` file are authoritatively and unconditionally replaced on every `apply` invocation.
- **Rerun recovery**: Because of unconditional replacement, running the command again recovers the correct state if any files are manually altered, corrupted, or deleted.
- **No automatic deletion**: Unmanaged files are not automatically deleted merely because a repository declaration is absent from the active configuration.

### Binary definitions

```yaml
- name: application
  format: deb
  commands: [application]
  source:
    provider: github
    repository: owner/repository
    assets:
      amd64: '^application-amd64\.deb$'
      arm64: '^application-arm64\.deb$'
```

| Field | Required and accepted value | Interactions |
| --- | --- | --- |
| `packages.binaries[].name` | Required definition name | Unique binary identity |
| `packages.binaries[].format` | Required: `deb` or `appimage` | Generic archives and installer scripts are not accepted |
| `packages.binaries[].commands` | Required unique list of executable basenames | Every command may be owned by only one definition |
| `packages.binaries[].source` | Required tagged mapping | `provider` selects exactly one shape below |
| `packages.binaries[].source.provider` | Required: `github` or `url` | Unknown or mixed provider fields are rejected |

GitHub source fields:

| Field | Required and accepted value | Interactions |
| --- | --- | --- |
| `packages.binaries[].source.repository` | Required GitHub repository | Latest non-prerelease release is selected |
| `packages.binaries[].source.assets` | Required non-empty architecture map of asset regexes | The definition applies only on listed architectures; exactly one release asset must match when applicable |
| `packages.binaries[].source.assets.amd64` | Optional asset regex | Selects an `amd64` release asset |
| `packages.binaries[].source.assets.arm64` | Optional asset regex | Selects an `arm64` release asset |
| `packages.binaries[].source.assets.arm32` | Optional asset regex | Selects an `arm32` release asset |

Fixed URL source fields:

```yaml
source:
  provider: url
  urls:
    amd64: https://downloads.example.com/application.deb
  sha256:
    amd64: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

| Field | Required and accepted value | Interactions |
| --- | --- | --- |
| `packages.binaries[].source.urls` | Required non-empty architecture map of HTTPS URLs | The definition applies only on listed architectures |
| `packages.binaries[].source.urls.amd64` | Optional HTTPS URL | Selects the fixed `amd64` artifact |
| `packages.binaries[].source.urls.arm64` | Optional HTTPS URL | Selects the fixed `arm64` artifact |
| `packages.binaries[].source.urls.arm32` | Optional HTTPS URL | Selects the fixed `arm32` artifact |
| `packages.binaries[].source.sha256` | Required non-empty architecture map of SHA-256 values | Key set must exactly equal `urls`; fixed URLs are not automatic binary-update targets |
| `packages.binaries[].source.sha256.amd64` | Optional SHA-256 | Required when `urls.amd64` is present |
| `packages.binaries[].source.sha256.arm64` | Optional SHA-256 | Required when `urls.arm64` is present |
| `packages.binaries[].source.sha256.arm32` | Optional SHA-256 | Required when `urls.arm32` is present |

Architecture-map keys are `amd64`, `arm64`, and `arm32`. Host aliases normalize
`x86_64`/`amd64` to `amd64`, `aarch64`/`arm64` to `arm64`,
and `arm32`/`armv7`/`armv7l`/`armhf` to `arm32`.

## `tools`

```yaml
tools:
  rust: stable
  go: latest
  node: lts
  python: "3.13"
```

`tools` is optional. If present, at least one child is required. Every field is
optional within the mapping.

| Field | Accepted value | Omission and interactions |
| --- | --- | --- |
| `tools.rust` | Rustup-native `stable`, a `major.minor` version channel, or an exact `major.minor.patch` release | Required by `packages.cargo`; `stable` and two-component versions are moving update targets |
| `tools.go` | `latest` or a two/three-component numeric version | Only `latest` is a moving update target |
| `tools.node` | `lts`, `latest`, or a one/two/three-component numeric version | Required by `packages.npm`; only `lts` and `latest` are moving update targets |
| `tools.python` | A two/three-component numeric version | No Python update field exists |

Numeric components contain only decimal digits. Numeric selectors are pinned;
omitting a tool requests no installation or update for it.

## `fonts` and `dotfiles`

```yaml
fonts:
  nerd: [GeistMono]
dotfiles:
  packages: [bash, bat, starship]
```

| Field | Required and accepted value | Omission and interactions |
| --- | --- | --- |
| `fonts` | Optional mapping; when present it must contain `nerd` | Omission requests no font action |
| `fonts.nerd` | Required unique list of definition names | Selects Nerd Fonts families |
| `dotfiles` | Optional mapping; when present it must contain `packages` | Omission requests no dotfile action |
| `dotfiles.packages` | Required unique list of definition names except `.` and `..` | Names select direct children of the embedded dotfiles root; Stow and backup-before-adoption policy are fixed |

## `integrations`

```yaml
integrations:
  docker:
    add_user_to_group: true
    logging:
      driver: local
      max_size: 10m
  virtualbox:
    add_user_to_group: true
  vscode:
    extensions: [publisher.extension]
```

`integrations` is optional. If present, at least one integration is required.
Integrations configure existing products and do not install them. The config
parser does not require a corresponding package declaration; execution requires
the product's CLI to exist, whether preinstalled or declared elsewhere in the
same configuration.

| Field | Required and accepted value | Omission and interactions |
| --- | --- | --- |
| `integrations.docker` | Optional mapping containing `add_user_to_group` and/or `logging` | Docker CLI must be available at execution |
| `integrations.docker.add_user_to_group` | Optional, true only | Omission preserves membership |
| `integrations.docker.logging` | Optional mapping | If present, `driver` is required; Cozydot atomically merges only the owned `log-driver` and optional `log-opts.max-size` keys into valid `/etc/docker/daemon.json`, preserving unrelated valid JSON. Cozydot does not restart/reload Docker or active containers, so the operator must restart/reload Docker as appropriate to activate the setting |
| `integrations.docker.logging.driver` | Required in logging; only `local` | Sets the owned daemon logging driver |
| `integrations.docker.logging.max_size` | Optional Docker size | Omission leaves an existing `log-opts.max-size` value untouched |
| `integrations.virtualbox` | Optional mapping | If present, `add_user_to_group` is required |
| `integrations.virtualbox.add_user_to_group` | Required, true only | Omission of the integration preserves membership; VirtualBox CLI must be available at execution |
| `integrations.vscode` | Optional mapping | If present, `extensions` is required |
| `integrations.vscode.extensions` | Required unique list of VS Code extension IDs | VS Code CLI must be available; unrelated extensions are preserved |

## `desktop`

```yaml
desktop:
  theme: dark
  terminal: wezterm
  idle:
    timeout: 15m
    dim: false
  gnome:
    extensions: [example@example.org]
    dock: true
    rounded_corners: true
```

`desktop` is optional. If present, at least one child is required.

| Field | Required and accepted value | Omission, applicability, and interactions |
| --- | --- | --- |
| `desktop.theme` | Optional: `light` or `dark` | GNOME/Cinnamon only; omission preserves theme |
| `desktop.terminal` | Optional executable basename | GNOME/Cinnamon only; command existence is checked after installation phases |
| `desktop.idle` | Optional mapping containing `timeout` and/or `dim` | GNOME/Cinnamon only |
| `desktop.idle.timeout` | Optional duration | Omission preserves timeout; sub-second results and values above `u32::MAX` seconds are rejected because the desktop backend stores whole seconds |
| `desktop.idle.dim` | Optional boolean, both `true` and `false` | Omission preserves dimming state |
| `desktop.gnome` | Optional mapping containing at least one GNOME child | Allowed on GNOME and Cinnamon; applied on GNOME and skipped on Cinnamon |
| `desktop.gnome.extensions` | Optional unique list of GNOME extension UUIDs | GNOME only; newly installed extensions may require logout/login before enabling |
| `desktop.gnome.dock` | Optional, true only | GNOME only; omission preserves dock state |
| `desktop.gnome.rounded_corners` | Optional, true only | GNOME only; omission preserves rounded-corner state |

Any neutral desktop field (`theme`, `terminal`, or `idle`) requires normalized
GNOME or Cinnamon. A `gnome` mapping also rejects `none`, so its GNOME-only
children can be applied on GNOME or deliberately skipped on Cinnamon.

## `updates`

```yaml
updates:
  apt: full
  flatpak: true
  tools:
    rust: true
    go: true
    node: true
  packages:
    cargo: true
    npm: true
    binaries: true
  fonts: true
```

`updates` is optional. If present, at least one effective child is required.
Every boolean leaf is true only; omit a target to disable it.

| Field | Required and accepted value | Prerequisite and scope |
| --- | --- | --- |
| `updates.apt` | Optional: `standard` or `full` | `standard` runs `apt-get upgrade`; `full` runs `apt-get full-upgrade`, then `apt-get autoremove --purge`, which permanently removes automatically installed packages that APT considers unnecessary |
| `updates.flatpak` | Optional, true only | Requires `packages.flatpak`; updates configured applications and required related refs |
| `updates.tools` | Optional mapping containing at least one tool leaf | Empty mapping is invalid |
| `updates.tools.rust` | Optional, true only | Requires `tools.rust: stable` or a two-component Rust version channel such as `1.75` |
| `updates.tools.go` | Optional, true only | Requires `tools.go: latest` |
| `updates.tools.node` | Optional, true only | Requires `tools.node` equal to `lts` or `latest` |
| `updates.packages` | Optional mapping containing at least one package leaf | Empty mapping is invalid |
| `updates.packages.cargo` | Optional, true only | Requires `packages.cargo`; updates only configured packages |
| `updates.packages.npm` | Optional, true only | Requires `packages.npm`; updates only configured packages |
| `updates.packages.binaries` | Optional, true only | Requires at least one GitHub-provider binary and updates only GitHub definitions |
| `updates.fonts` | Optional, true only | Requires `fonts.nerd`; updates only configured families |

## Examples

[`examples/config-v1-beginner.yaml`](examples/config-v1-beginner.yaml) is a
small starting point. [`../configs/full.yaml`](../configs/full.yaml) is a
practical comprehensive workstation preset, not a synthetic inventory of every
accepted field or value. This reference, rather than `full.yaml`, defines the
complete public contract.
